# CITF对照ARBoids逐项审查报告

审查日期为2026年11月1日。审查对象为本次上传的CITF论文、实验方案、Codex任务文件及完整代码包。本报告不沿用此前关于PCF-MBRL、CV或其他历史分支的研究定位。

## 一　审查结论

当前主任务为六艘防御艇，冻结泛化安排为3、4、5、7、8艇。“第三艘艇”指被评价艇对之外的某一个队友，不是把系统限制为三艇。论文、计划、实验清单及实际控制接口均支持这一判断。

CITF已经建立可以作为独立方法论文展开的研究内容。其控制方法以完整候选配置为条件评价艇间交互，其关键学习机制以短时真实运动和几何风险训练Transformer，并将预测结果用于当前融合选择。这个完整控制方法加关键学习机制的组织层次，与ARBoids的研究方式对应。

当前材料仍是有开发依据的研究初稿与实施包。修订模型没有完成正式独立训练、主要学习消融、完整基线和高保真验证。代码具备可运行的预测、训练与CI控制核心，但仍有需要在正式训练前补齐的定义与执行接口。因此，不能把它验收为实证已经完成的投稿论文，也不能把Codex交付包描述为已经具备全部无歧义的一键实验流程。

本报告不建议更换CI研究方向、恢复CV、重新采用长期价值规划或新增一套大型实验矩阵。后续修改主要是使已经声明的方法、输入、执行和证据保持一致。

### 3.2 “第三艘艇”表示其他队友

在六艇配置中，评价艇1与艇2时，可以写成

\[
\psi_{12}^{\theta}
\bigl(\mathcal H_t;g_1,g_2,g_3,g_4,g_5,g_6\bigr).
\]

艇3、艇4、艇5和艇6都是这对艇之外的其他防御艇。改变其中任一候选可能改变候选关系注意力，进而改变艇1、艇2的评分。是否产生显著变化取决于实际态势与训练结果。

六艘防御艇共有15个无序艇对。当前网络不是只评价一个三艇组合，也没有单独定义三元势函数。更准确的表述是“艇对评分以整队候选配置为条件”。

建议把全文说明中的“第三艘艇”改为“被评价艇对以外的其他防御艇”。图3保留局部三实体示意，但图注写明“从六艇系统中抽取一对被评价防御艇及一个其他队友，其他防御艇省略”。不需要改变主任务或重新设计图片所表达的算法。

### 3.3 源码中的数字3要区分用途

`ActorAdap(6,8,3,512)`中的3是源网络的输出维数，即两个归一化推力通道与一个融合输出；这里的6和8也属于特征维度，不是艇数声明。环境类原始默认值为3，但CITF包装器显式传入实际防御艇数量。

源环境的学习型攻击者观测还包含“最近三艘防御艇”的局部观测定义。该处限制的是攻击者可见信息，而非防御艇总数。图7实施时必须统一说明攻击者观测权限，并使各防御方法面对同一个对手配置。

## 五　CITF的学术贡献是否清楚

### 5.1 可以保留的创新主轴

CITF将原有固定艇对候选评分扩展为以整队当前候选配置为条件的预测评分。模型利用短时实际反馈运动估计同步最小间距的分布，并以期望几何代价参与当前联合选择。这条链具有明确的输入、学习对象和控制作用。

\[
\text{当前候选配置}
\longrightarrow
\text{共同短时运动与间距分布}
\longrightarrow
\text{几何交互评分}
\longrightarrow
\text{当前整队融合指令}.
\]

输入仍是当前控制候选，输出仍是当前融合系数。没有终局成功概率、长期Bellman价值、融合计划或事后干预模块。源策略自身的强化学习训练属于控制来源，新增Transformer只学习短时物理后果。

这种完整控制方法与关键学习机制的组合，可以作为独立方法论文的研究框架。是否达到已发表ARBoids相近的贡献说服力，取决于新模型能否在同条件比较中改善候选判断，并带来可重复的完整任务收益。

### 5.2 不宜单独作为创新证明的内容

“第三方候选可以影响艇对评分”首先是模型结构能力。它还需要训练后模型与去候选上下文版本的实际比较，才能证明这种能力被有效利用。

“使用Transformer”只说明实现模型。“零点质量、期望风险公式、对称读出”使定义更精确，但其增量应由现有的预测训练、校准与控制指标检验。源偏好仍然是任务机动依据，论文不应把纯接近代价解释为完整的拦截价值。

风险界和有限候选选择误差界解释预测与搜索的关系，不宜作为独立理论突破。当前正文使用这些关系辅助方法解释是合适的。

## 七　代码与方案之间需要补正的具体事项

以下位置均相对于当前交付包。审查识别的是已声明的定义、实现与验收条件之间的缺口，不要求增加新的研究方向。

### A01　停止区间目标缺少剩余任务时间

**位置**　论文II-B、III-C、III-F；`contracts.py:25–33`；`bridge.py:64–74,89–102`。

标签规定距离在预测时域与真实任务终止之间的较短区间统计。当前历史、候选和名义输入未包含剩余任务时间。

**实际检查**　构造两个位置、速度、历史和候选完全相同的根状态，仅将任务时间分别设为0和79.8 s，全部模型输入相同。实际短分支分别有9步和1步有效数据，最大艇对标签差约3.2620 m。这个检查是受控接口构造，不是自然采样场景统计。

**处理**　显式加入剩余时间或已知剩余预测长度作为公共上下文，更新输入schema、特征说明和训练/评价接口。可由已保存根步恢复的数据补齐真实字段；缺失来源的数据重新采集。不得把真实未来捕获或碰撞时刻作为网络输入。任务时限属于当前已知信息，这项修复不引入CV。

### A02　协议声明与实际环境可静默分离

**位置**　`contracts.Protocol`；`bridge.py:35–42`。

`World`只把环境模式、时限和防御艇数量传给TADEnv。协议中的控制步长、半径和径向判负等字段没有逐项应用或拒绝。

**实际检查**　声明0.1 s、保护半径18 m、关闭径向判负时，环境仍执行0.2 s、15 m、径向判负。当前默认值相符，所以该检查没有推翻原48任务默认协议；问题在于后续修改参数会静默失效。

**处理**　使用单一有效协议实例。暂不支持改变的字段应启动即报错；支持改变的字段要显式设置并读取实际值验收。数据、模型和任务结果保存实际生效协议及哈希。不要在本轮审查中擅自把80 s改成60 s。

### A03　正式冻结检查未锁定完整控制器

**位置**　`contracts.py:58–63`；`evaluate.py:11–33`。

冻结函数只验证冻结标记、预测权重和任务文件哈希。实际评价另外检查源权重与环境源码，但没有锁定风险模式、候选bank、预算、轮数、物理协议数值和运行时版本。

**实际检查**　缺少这些字段的最小冻结清单能通过。仅改变`--risk`或求解参数就可能执行不同控制器，却仍被记为同一冻结方法。

**处理**　在正式任务开始前对完整有效运行配置做规范化哈希；所有算法特有参数、特征schema、源/预测权重、协议、代码及任务角色都须一致。每次结果落盘完整配置。程序错误修复与算法变更分别登记，不能通过重新写一张清单覆盖已看过的测试身份。

### A04　布局防泄漏依赖可改名标识

**位置**　`contracts.py:37–45`；`train.py:24–48`。

现有校验按字符串`layout_id`及split判断。相同真实初始几何改一个名字即可越过当前交叉划分检查。

**实际检查**　在合成对抗校验中复用完全相同数据和scene seed，仅修改layout_id，现有守卫未拒绝。该结果只证明守卫不足，没有发现真实实验已经发生此类污染。

**处理**　增加由布局生成版本、实际初始几何及艇数得到的`layout_fingerprint`或`geometry_family_id`。同一几何在不同机动性与未来扰动下共享划分家族，任务id再区分具体条件。名称、随机种子和内容指纹同时登记。存在多个扰动时按布局成簇统计。

### A05　CITF访问状态补采尚未接入

**位置**　论文III-F末段；方案7.2；`collect.py:51–75`。

文档要求第三阶段使用当前冻结CITF采集其访问的中后期状态。当前采样脚本始终构建`Controller(source, model=None,...)`，实际行为策略为快速物理CI；没有加载预测检查点的采样参数。

**处理**　增加行为控制器选择与检查点参数，验证输入语义、源权重和环境身份。记录行为预测器哈希、搜索配置、采集迭代和根时间。普通物理行为采样与CITF行为采样分别保存。短分支标签仍由真实反馈执行产生，不使用网络输出代替真实标签。

### A06　源融合中心的实际映射需要写清

**位置**　论文III-A/B；`bridge.py:29–32`。

源码对原Adapter输出a使用额外确定映射，等价为

\[
\bar g=\operatorname{sigmoid}(3.84a-1.92).
\]

原始a取0、0.5、1时，中心约为0.12786、0.5、0.87214。它沿用了开发代码的处理，当前初始两通道使用相同中心。论文若直接说中心就是原Adapter输出，定义不够精确。

**处理**　说明继承映射和参数出处，或在开发阶段明确更换后重新训练与比较。它不是Transformer新贡献，不能只为新方法调映射而不给直接匹配对照相同条件。候选控制输入还应写出归一化
a=(u−250)/750，避免物理单位表述与网络接口混淆。

### A07　正式长期训练的恢复入口不足

**位置**　`train.py:36–78`；方案8.3、15、16。

脚本保存best，正常结束时才保存含优化器状态的last，没有`--resume`与定期恢复点；CUDA随机状态也未完整纳入恢复。中断运行可能丢失中间优化状态。

**处理**　周期保存最近检查点，记录优化器、调度器、采样生成器、CPU/CUDA随机状态、更新计数、数据/协议/特征哈希及验证记录。恢复时检查全部身份，进行“连续训练与中断恢复”一致性回归。该项是既有五次训练计划的执行支持，不是新实验。

### A08　逐步控制证据未由评价器完整导出

**位置**　`bridge.py:119–121`；`evaluate.py:34–44`；方案6.2、16。

控制器返回候选、评分和融合系数，但评价器只写任务摘要、时延及平均调用数。图3的实际候选关系、图4的轨迹和行为分析不能仅由摘要重建。

**处理**　按任务保存时间、状态、源控制、所选系数、实际推力、被评价配置及评分、终止事件和时延分项。候选大数组可分块压缩，并保存索引。所有展示轨迹使用批量评价中的任务id，摘要由逐步记录自动汇总。

### A09　两项实验定义仍需落为唯一配置

**位置**　方案9.1、9.3、11.3。

强MARL仍写“MAPPO或既有强MARL”，独立选择仍写“共同参考或候选边缘分布”，对手学习预算及检查点阶段未固定。方向明确，但Codex不能在看过最终结果后选择有利定义。

**处理**　在开发注册清单中确定一个强MARL实现与选模规则；明确独立选择究竟是固定共同参考的一次局部选优，还是对预先固定分布求边缘期望。二选一固定主版本即可，不要求新增全部替代。对手实验记录固定攻击集合、真实更新阶段、适应预算和原任务回测。

### A10　历史编码缓存的正文描述尚未完全实现

**位置**　论文III-D首段；`bridge.py:114–118`。

模型支持历史编码相关结构，但当前每批完整候选都重新调用整模型，未在控制周期外层显式缓存一次历史表示。初始集合和邻域集合会重复编码。

**处理**　在一次观测周期内构造缓存并用于所有新增配置，状态变化后失效；训练保留正确梯度路径。若暂不实现缓存，就将正文改成实际执行，不能把尚未得到的加速计入时延分析。

### A11　分布评分对照的名称应与数学对象一致

**位置**　`model.py`中的`det_risk`；论文III-E。

论文将mu准确称为非负修正高斯之前的“位置参数”。代码的确定性评分使用mu。由于D=max(0,Z)，其均值为

\[
\mathbb E[D]=\mu\Phi(\mu/\sigma)+\sigma\varphi(\mu/\sigma).
\]

因此，若补充对照命名为“均值距离确定性风险”，应使用上述均值；继续使用mu时称为“位置参数确定性风险”。当前主期望风险公式和零点似然已通过测试，此项不是要求推翻分布模型。

### A12　源协议与原复现差异必须闭环

**位置**　`audit/original_replay.json`、源训练元数据、Codex第一阶段。

已知58/64与57/64的存档差异仍未定位到每场首个分叉。源元数据足以补充六艇、种子和训练量，但奖励、课程、实际源码和验证选模仍须查对应配置。

**处理**　按源观测、源指令、融合中心、候选、评分、推力、RNG、积分、终止依次定位最早差异。保留旧结果身份。无法找回旧执行版本时，修订实现独立命名并在同协议下重训比较，不修改存档来追求一致。

## 八　对Codex方案明确程度的评价

| 维度 | 当前评价 |
|---|---|
| 研究边界 | 明确，CI-only且排除CV |
| 主任务规模 | 明确，六艇 |
| 对照体系 | 基本明确，强MARL与独立选择定义需最后锁定 |
| 训练数据组织 | 定义较完整，物理布局身份与剩余时间需要补正 |
| 学习目标 | 清楚，预测/风险/选择均源于短时几何 |
| 已有核心代码 | 可运行并通过现有测试 |
| 正式冻结与恢复 | 原理写明，实现仍不足 |
| 源训练与强基线包装 | 已列待开发，不是已有完整工具 |
| 高保真及对手训练 | 任务明确，接口与完整结果尚未完成 |
| 论文更新 | 有版本边界与待补规范，应继续保持 |

总体属于“可以交给Codex开展后续研究开发的详细任务包”，还不是“所有细节已封闭、无需再判断即可一键得到最终论文的执行包”。以上A01—A12补正完成后，再进入正式冻结与大规模证据生产更稳妥。

## 九　允许保持不变的内容

保留CITF名称、六艇主任务、当前融合变量、短时运动与几何风险监督、候选Transformer、当前联合求解以及五章七图。保留两项主要学习消融和现有机制表。不增加CV，不增加长期终局价值，不恢复四配置矩阵，不要求每项模块单独完成整套泛化和VRX。

方法设计可以在开发阶段修订，正式比较固定共同条件。发现实现缺口时修复对应接口，不据此不断更换什么才算创新的标准。

## 十　最终验收意见

CITF的研究对象和贡献组织已经具备与ARBoids相近层次的独立方法论文框架。当前证据能够支持旧开发原型的同条件增量，尚未支持修订定稿模型的完整学术结论。

“六艇是否固定”已经有明确答案，主任务固定六艇，其他艇数用于冻结评价。模型中的第三方条件指向整队信息，不能被解释成三艇专用设计。

“论文是否彻底做实”仍需在修订实现、正式学习、贡献消融和系统验证全部对应以后判断。当前最有价值的工作是补齐A01—A12与已列待实现接口，再按既定P0—P8执行，而不是重写研究主线或另加模块。
