# 后续修复：预测价值与200毫秒规划预算

2026-10-06，用户明确要求继续解决此前两轮主判据未通过、六艇对同族短时方案优势不明确，以及20秒方案规划p95超过200毫秒的问题。此前停止第二轮后报告的约定到此结束；已有数据继续保留为对应旧版本的结果，后续工程开发可使用这些已经观察过的数据。

## 先修计算实现

新增批量Actor和数组形式的Boids、观测生成，保持物理积分、冻结权重与官方CBFpy求解器。预测中跳过未用于评分的奖励和重复约束残差计算，实际控制仍记录残差。批量网络改变浮点求和顺序，必须验证数值误差，不能宣称与原实现逐位相同；同一新实现的串行和并行输出则要求逐元素一致。

第一项独立时间测试采用四个已有六艇场景，各机动系数一个。只测稳定运行，单独报告冷启动；不与开发评估同时运行。若控制方法随后变化，最终方法必须重新测试。

## 第一阶段有限开发

仅使用旧六艇开发集的32个场景，以及此前20秒方法失败的两个已知场景173180012、173190003。两类分别汇总，新增失败场景不当成随机验证样本。比较固定的8种长时配置：执行区间1/2秒、后续策略为CBF/持续当前候选、捕获裕度0.5/1.5米，后续均20秒；混合系数均为1。另运行相同执行区间与捕获裕度的4种零后续短时消融，以及冻结CBF、旧开发选出的固定守卫策略和保持旧评分的批量20秒版本。共15种方法×34个旧场景。

运行前的两次旧失败轨迹诊断发现：所有候选都预测失守时，旧评分的“终止时间+剩余捕获估计”可能偏好更早失守。新长时与短时配置共同修正为在失败类别内优先推迟失守，成功类别和碰撞/失守优先级保持不变；额外保留的旧评分版本用于分离该修复与后续价值的作用。

目的：区分计算加速是否改变原结果、CBF后续是否低估持续机动的作用，以及过于乐观的捕获预测是否导致成功损失。后续若需新增方法，必须先说明具体失败机制，再明确有限候选，不在未见场景上边调参边评价。

## 最终独立确认的要求

进入全新确认前，第二阶段开发使用前两批已经观察过的全部256个六艇场景，每批128个。固定比较第一阶段表现较好的CBF后续2秒执行、持续候选后续1/2秒执行三个长时版本，两个对应短时消融、CBF、固定守卫策略，以及旧失败评分版本，共8种方法。捕获裕度统一0.5米，长时后续20秒。不能将这256个场景重新称为独立确认。采用单独验证的JIT积分、Boids和观测生成实现，闭环预测与数组参考使用数值误差检验；实际环境不变。最终确认和时延使用同一JIT版本。

只有开发中对成功率和效率都有足够收益的最终版本进入确认。六艇仍为主场景，攻击艇机动系数仍为1.5、2、2.5、3。拟固定512个全新场景，各档128个，场景种子193160000 + agility_index×10000 + repeat，噪声种子加1000000；确认开始前冻结最终代码、参数和方法名单，核对与全部此前名单不重叠。

主比较必须包括CBF、同候选同信息同执行间隔的短时消融、开发选出的最强固定策略。长时配置在第二阶段完整256场景中依次按成功数最多、碰撞数最少、平均封顶耗时最低选择；同样从两种短时配置中选择最强短时版本。如果其执行间隔不同于最终长时配置，额外将它加入主要对照，要求所有主要对照同时满足标准。旧失败评分、2秒执行和CBF后续的20秒版本，采用同一加速实现保留为版本对照。任务成功和碰撞使用原始判定，捕获耗时中所有未捕获回合按80秒计。新方法相对每个主对照的平均封顶耗时至少降低10%，配对分层10000次自举区间排除零改善，观察到的成功数不少、碰撞数不多，且配对成功率差的保守下界至少为−3个百分点。主要对照需要全部满足，不选其中有利一项。

为涵盖前两次确认机会，跨三次强主张采用98.333333%区间，旧结果仍保留其原定区间作描述。配对成功概率的胜负分别用尾概率0.008333333的Clopper–Pearson下界和上界相减；不能用相同结果的退化自举区间证明不劣。性能和独立时延都必须来自同一个最终实现；完整规划调用p95须低于200毫秒，同时报告p99、最大值和超时比例。独立时延覆盖32个旧六艇开发场景的完整回合，比较串行和五工作进程并行输出，冷启动单列。最终配置、代码、统计分析、场景名单及旧数据和时间测试的哈希均须在运行全新512场景前冻结，不做中途选参或提前停止。保留前述旧版本失败结果，不能用新的成功结果覆盖它们。
