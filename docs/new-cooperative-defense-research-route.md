# 基于候选交互的联合策略融合：方法与论文证据方案

当前方法只保留独立工作的第一项机制（M1）：基于候选交互的联合策略融合。复现基准是冻结的纯 M1/F10 检查点及其匹配独立选择对照。历史实验数据、源代码快照和证据包保留原始身份；当前论文与执行入口以本文和 `joint_fusion.py` 为准。

## 1. 研究问题与方法贡献

ARBoids通过状态相关的融合权重调节学习策略与Boids策略的参与程度，并通过队友观测及Boids特征利用群体信息。本文研究不同艇的融合候选如何共同形成有效的团队运动。[ARBoids原文](../paper/2026_ARBoids_Adaptive_Residual_Reinforcement_Learning_With_Boids_Model_for_Cooperative_Multi-USV_Target_Defense.pdf)

**基于候选交互的联合策略融合（Joint Policy Blending Based on Candidate Interactions）。** 将源策略的局部融合建议与候选机动之间的艇对交互关系纳入统一优化，使规则策略和学习策略的融合从各艇局部选择扩展为整队联合决策。主要证据来自候选集合、源策略、预测信息一致的联合／独立选择比较。

## 2. 执行器候选与源策略偏好

令 \(u_i^L,u_i^B\) 为第 \(i\) 艘艇的当前学习与 Boids 推力。两个执行器分别选择融合系数：

\[
u_i=g_i\odot u_i^L+(1-g_i)\odot u_i^B,
\qquad g_i=(g_{i,1},g_{i,2})\in[0,1]^2.
\]

每个推力分量均位于两个原始控制分量之间。源策略的原始融合建议 \(\theta_i^{\mathrm{src}}\) 映射为

\[
p_i=0.02+0.96\theta_i^{\mathrm{src}},\qquad
b_i=\sigma\!\left(2\tanh\frac{\operatorname{logit}(p_i)}2\right).
\]

主比较中每个执行器使用 \(\{0,b_i,1\}\)，形成每艇九个候选。联合和独立选择使用相同表示。源策略偏离代价为

\[
\phi_i(k)=\frac12\sum_{a=1}^{2}
\left(\frac{g_{i,a}^{k}-b_i}{0.4}\right)^2.
\]

## 3. 候选反馈预测与联合选择

名义预测时域为3.2秒，积分步长为0.1秒，学习与Boids命令每0.2秒按预测观测刷新。候选融合系数在一次预测内固定，实际控制每0.2秒重新决策。基础预测用公开速度近似邻艇运动，形成候选路径 \(\hat p_i^k\)。

\[
\psi_{ij}(k,\ell)=
\left[7-\min_{s\in\mathcal T_H}
\|\hat p_i^k(s)-\hat p_j^\ell(s)\|\right]_+^2,
\qquad
\boldsymbol k^*\approx\arg\min_{\boldsymbol k}
\left[\sum_i\phi_i(k_i)+32\sum_{i<j}\psi_{ij}(k_i,k_j)\right].
\]

该目标显式依赖双方候选。固定队友选择后，单艇变更同时改变本艇偏好代价和涉及该艇的全部艇对代价，因此不同团队配置下的局部选择可以不同。交互项为有限权重的软风险惩罚；捕获、碰撞与突破由实际闭环回合检验。

当前执行器版本使用宽度128的束搜索及三轮坐标更新。细化版本继续细化保留的束端点，并进行一轮艇对块更新；仅当源偏好偏离与预测交互代价均不劣于原联合解时接受细化。基础联合选择与细化版本在结果中分别标识。

独立选择读取完全相同的候选路径和艇对代价，以队友源偏好概率
\(p_j(\ell)\propto\exp[-\phi_j(\ell)]\) 计算

\[
k_i^{\mathrm{ind}}=\arg\min_k
\left[\phi_i(k)+32\sum_{j\ne i}\sum_\ell
p_j(\ell)\psi_{ij}(k,\ell)\right].
\]

两者的主要区别是是否联合确定候选组合。计算成本分别报告候选预测与组合搜索，不把共同预测资源误写为相同总耗时。

## 4. 保留的训练、预测与部署能力

冻结源Actor、解析候选选择、独立选择消融、完整反馈预测、目标运动预测、整队候选学习和普通候选表达对照均属于M1及其配套比较。解析纯M1基准不需要新增价值模型即可独立推理。可选整队学习使用完整事实回合及实际团队结果，预测模型从事实轨迹拟合；它们保持各自的设置与检查点身份，不替换已冻结的解析M1证据。

| 模块 | 职责 |
|---|---|
| `train/joint_fusion.py` | M1源策略加载、候选预测、控制、完整回合评估与命令入口 |
| `train/actuator_fusion.py` | 执行器候选库、联合／独立选择、完整反馈预测与整队候选策略 |
| `train/fusion_prediction.py` | 共享预测特征、数值映射与固定批宽推理 |
| `train/fusion_training.py` | 完整事实回合、公共目标运动拟合与整队候选学习 |
| `train/mechanism_controls.py` | 状态／候选注意力等M1替代对照 |
| `vrx/run_gate_contribution.py` | 公共测量输入下的M1闭环部署与候选推力执行 |
| `train/tests/test_actuator_fusion.py` | M1控制、选择、预测与学习回归检查 |

源策略权重、物理动力学、Boids控制、控制周期和任务判定均由对应检查点与协议决定。清理前的纯M1检查点继续读取其原有设置；不把不兼容的历史模型静默解释成M1。

## 5. 评价协议与已有结果

主要数值任务保留作者源码协议：80秒时限、0.05秒物理积分、0.2秒控制间隔，保护半径15米，捕获和艇间碰撞阈值5米。源码失败还包含攻击艇比全部防御艇更接近目标的径向越过条件；该事件与实际进入保护区分别记录。

同一比较共享布局、未来扰动、艇数与机动性。256场源套件含64布局各四个未来，另外三个套件各200场，共856场开发回合。同一布局的未来样本在区间估计中保持同簇。全部训练重复与救援／损害都保留；开发集不能重新称为冻结测试集。

六艇源策略从头完成100万步训练，种子42的结果为：

| 方法 | 成功数 / 856 | 成功率 |
|---|---:|---:|
| SAC | 118 | 13.8% |
| RP | 341 | 39.8% |
| ARBoids | 578 | 67.5% |
| 独立融合选择 | 726 | 84.8% |
| 联合融合选择 | 795 | 92.9% |

联合选择相对ARBoids提高25.4个百分点，相对匹配独立选择提高8.1个百分点。后者包含112次救援和43次损害，布局簇自举区间为[5.3, 11.1]个百分点。联合选择的793次捕获、9次碰撞和52次源码失败，与独立选择的723、20和110分别比较；另有2次与3次时限防御成功。

五个独立源策略训练种子全部保留：

| 种子 | ARBoids成功数 | 独立选择成功数 | 联合选择成功数 |
|---|---:|---:|---:|
| 42 | 578 | 726 | 795 |
| 43 | 355 | 385 | 404 |
| 44 | 584 | 773 | 780 |
| 45 | 615 | 736 | 758 |
| 46 | 675 | 707 | 755 |

联合／独立选择平均成功率分别为81.6%和77.7%，联合选择的平均增量为3.9个百分点，各种子均为正。状态注意力与候选注意力替代在种子42上分别为626/856和665/856；它们共享24,576条教师查询、24,000次更新与192,769个参数，执行时独立选择自身候选。

三艇源迁移至六艇的历史结果单独保留：原联合选择738/856、细化联合选择763/856、独立选择671/856。细化联合选择的10.7个百分点优势包含144次救援和52次损害。八场历史VRX开发比较中，原联合前驱捕获8/8，细化联合选择7/8且发生一次碰撞，独立选择4/8，迁移源策略2/8；这些结果不与数值环境的时限及判定混用。

## 6. 论文证据与后续验证

- 主要贡献比较：同源策略、同候选、同预测的联合／独立选择，报告成功、碰撞、源码失败、救援、损害与捕获效率。
- 替代比较：原Adapter、状态注意力、候选注意力、单一队友参考预测、独立选择与完整联合选择，保留各自的信息与训练预算。
- 独立重复：每个种子分别训练共同源策略，所有比较共享该种子检查点，不以最佳种子替代跨种子统计。
- 行为证据：同场景候选预测、实际轨迹、融合系数和艇间距离，连接联合选择与实际任务后果。
- 泛化与部署：冻结方法后评价独立布局、艇数、机动性和VRX任务；保留所有失败及模型失配现象。

现行稿件为 `paper/interaction_aware_residual_rl.tex`。历史证据保存在原实验目录、证据包及 `results.md`；旧结果不改写为当前方法的结果。

## 7. 复现入口

```bash
python -X utf8 train/joint_fusion.py create --source <source.pth> --output <m1.pth>
python -X utf8 train/joint_fusion.py evaluate --checkpoint <m1.pth> --tasks <paired-tasks.json>
```

`create --selection independent`生成匹配独立选择。可选整队候选学习从带完整反馈预测的M1模型开始：

```bash
python -X utf8 train/joint_fusion.py create --source <source.pth> --output <m1-feedback.pth> --task-feedback
python -X utf8 train/joint_fusion.py train --checkpoint <m1-feedback.pth> --output <m1-trained.pth>
python -X utf8 train/joint_fusion.py collect --checkpoint <m1.pth> --tasks <paired-tasks.json> --output <trajectories.pth>
python -X utf8 train/joint_fusion.py fit-motion --checkpoint <m1.pth> --data <trajectories.pth> --output <m1-motion.pth>
```

训练、收集、预测拟合和解析基准评估按各自输出与配置区分。历史模型复现直接读取对应的纯M1检查点，不用新默认配置覆盖其设置。
